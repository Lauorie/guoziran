# 立项依据的写法

本章回答「为什么做」。从科学论证出发：重要性、缺口、科学问题、假设、切入点都已写在 `scientific_case.yaml` 中，本章把它们写成连贯的论证，并给出证据。

## 写什么

| 必写 | 不写 |
|---|---|
| 重要性；国内外现状与局限；缺口；科学问题；假设与否定条件；切入点；科学技术价值；术语界定；研究对象与目标人群的差异 | 实验步骤、技术路线、样本量设计、年度安排等研究方案细节 |

立项依据写到假设与切入点为止。「怎么做」放进研究内容，本章只用一句话衔接。

## 怎么写

### 结构

一般按下面的顺序。小节用 `\subsubsection`，小节标题可按课题改写。

1. **研究背景**：研究对象为什么重要，核心瓶颈是什么，为什么现在值得做。一到两段，不写教科书式科普。
2. **国内外研究现状**：按主题分条。小节标题写判断，不写名词短语。每条先写已知（带引用），再写局限。最后一段汇总缺口，引出科学问题。
3. **科学问题与研究假设**：科学问题、假设、分假设与否定条件，措辞与科学论证一致。
4. **研究切入点**：本项目与最近工作的差别（`entry_point`），末尾一句衔接研究内容。
5. **科学技术价值**：单列一节。从科学问题推出理论、方法、应用三方面的价值，每条落到本项目的具体产出。

小节标题的例子：

- 好：「瘤周纹理的增量价值尚未在控制瘤内特征后检验」。
- 差：「瘤周区域」。

科学技术价值的例子：「理论上，检验瘤周纹理是否在控制瘤内特征后仍有增量；方法上，给出可复用的环带宽度选择流程；应用上，为术前分层提供一个可外部验证的评估工具。」不写「突破」「填补空白」「首次」。

### 论证主线

主线是：领域价值与已有证据 → 认知缺口 → 科学问题 → 假设。

- 先把瓶颈转写成待解释的关系、机制、性质或适用边界。每个瓶颈映射成一个有前文依据的约束，科学问题追问这些约束下的未知。不凭空新增约束。
- 科学问题用疑问句，追问「是什么、为什么、在什么条件下成立」。「能否构建/开发/实现……」是研究目标，不是科学问题。启发式检查：把主语换成「本项目」仍然通顺的，多半是目标。
- 假设用可证伪的陈述句预测结果，不写验证方式。问题中的每个关键约束，假设里都有对应的策略；假设中的每个关键策略，研究内容里都有落点。
- 假设之前以事实、文献和缺口为主。干预、比较、终点和技术路线放在假设之后，或留给研究内容。外部文献的方法描述可以作为现状证据，不等于本项目的方案。
- 方法术语只作现状背景或验证手段，不撑主线。每段主句的主语是科学问题、假设或认知缺口，而不是方法、技术或平台。检验办法：删去方法术语，段落仍然成立吗？这一段回答的是「为什么做」还是「准备怎么做」？
- 理论、机制、方法、应用导向的课题，只改变措辞与证据的重心，不改变这条主线。

问题与假设的写法细节见 `scientific_case_guide.md` 的「科学问题与假设的写法」。

### 证据与引用

- 凡是叙述研究现状、他人方法或结论、流行病学数据的句子都要引用，条件见 SKILL.md 规则 5 与 `evidence_wording.md`。
- 措辞不超过对应论断的 `support`：`multi_verified` 可写「多项研究表明」；`single_verified` 只写「有研究报道」；`unsupported` 不写成事实；`applicant_material` 按材料原样写。
- 一个段落讲几项研究，就逐项引用。
- 申请人已发表的论文，在相关处引用，说明团队已有积累。措辞按论文报告的内容写，不夸大。

### 措辞

评审不反感好结果，反感无对照、无证据，或用形容词代替论证。

| 类别 | 例子 | 改法 |
|---|---|---|
| 绝对化 | 国际领先、世界首创、国内首次、唯一 | 写清对照、指标与范围 |
| 填补空白式 | 填补空白、开创性、颠覆性 | 写清缺的是什么、本项目提供什么、用什么验收 |
| 无依据夸大 | 重大意义、关键作用、显著提升 | 给出指标、对照或统计依据；没有就删去 |
| 自我定性 | 具有创新性、具有先进性 | 用差别和证据代替判断 |

- ❌ 国际领先 → ✅ 在某数据集上，相比某方法，指标提升若干（样本量、检验）。
- ❌ 填补空白 → ✅ 针对某场景缺少某能力，提供某方法，以某指标验收。

### 专业可读性

读者是熟悉本学科、不一定熟悉这个细分方向的大同行。准确优先，不科普化。

- 一句话里并列动作、限定和因果过多时，拆成主张、依据、结论。不删必要的限定。
- 缩写、新概念和「这/其/该机制」都要能找到所指。缩写首次出现写全称。
- 抽象名词连用时，补上关系动词、指标或边界。
- 段内分清事实、缺口和结论；需要时补转折，不制造因果。
- 删去不增加准确性的修饰，保留不确定性和条件。

改写时保留已核实的事实、研究对象、限定、问题与假设的原意、引用命令、标签和 LaTeX 结构。无法在不改变含义的前提下改写的句子，保留原句，把风险记入 `stages.md`。

### 句式参考

以下是可替换的骨架，不照抄：

- 缺口：「研究沿 A、B 两条路线展开，但仍受限于：其一，……的假设在……条件下难以成立；其二，……与……之间的因果链尚不清楚。」
- 问题：「在约束 A、B 下，X 是否仍具有 Y 性质？」「X 的 Y 在什么条件下成立？」
- 假设：「[核心机制] 通过 [应对约束的策略]，可 [预期结果]，并相对于 [对照] 表现出 [增量]。」
- 衔接：「上述问题的检验思路与技术路线见研究内容。」

## 写完自查

逐项核对，结论与改动记入 `stages.md`：

- 科学问题、假设、术语与 `scientific_case.yaml` 一致；没有把目标、技术路线或验证终点写成问题或假设。
- 每条涉及文献或事实的句子，在 `evidence_map.yaml` 中找到对应论断，措辞不超过其 `support`。
- 没有写进本章 `must_exclude` 的内容。越界的段落移到应在的章节。
- 证据、缺口与问题对得上；没有把不可核实的推断写成事实。
- 术语、缩写首次出现时有界定，前后一致。
- 长句、指代、抽象名词、衔接和修饰：按上面「专业可读性」逐段看一遍。
- 绝对化与夸大的说法：按上面「措辞」逐句看一遍。

确定性部分由脚本检查：`chapter_check.py --section 立项依据`（内部编号、非标准占位、绝对化短语）与 `consistency_check.py`（引用是否入台账、引用句数字、过程说明、引用篇数下限）。
