# 各章写什么、不写什么

`config.yaml` 的 `sections[].must_exclude` 是机器可读的默认值，`case.py init` 把它写进 `section_plan.yaml`。本文解释这些边界，供填写 `must_include` 和补充 `must_exclude` 时参考。

| 章节 | 必写 | 不写 |
|---|---|---|
| 立项依据 | 重要性、缺口、科学技术价值（从科学问题推出理论、方法、应用三方面的价值，每条落到本项目的具体产出）、科学问题、假设与否定条件、切入点、术语界定、研究对象与目标人群的差异 | 实验步骤、技术路线、样本量设计、年度安排等研究方案细节 |
| 研究内容 | 总体目标、研究框架图（WisImage 生成；出图失败时的占位）、各研究任务（指标、必比基线、混杂控制、验证方式；每项用同一组小标题；每项一张设计图）、技术路线 | 展开的国内外研究现状 |
| 特色与创新 | 1–3 条创新，各说明与主流路线的差别 | 「首次」「国际领先」「填补空白」等无依据的绝对化说法 |
| 年度研究计划 | 按研究期限分年的任务与里程碑，逐年对应研究任务 | 研究背景 |
| 研究基础 | 申请人提供的论文、数据、平台、预实验；缺失项的占位 | 申请人没有提供的论文、数据或预实验结果 |
| 工作条件 | 申请人提供的平台与设备 | 申请人没有提供的平台或设备 |
| 摘要 | 科学问题、假设、主要内容、预期意义，术语与科学论证一致 | 内部编号 |
| AI 使用说明 | 运行日志中记录过的 AI 使用 | 日志中没有记录的使用 |

立项依据写到假设与切入点为止。「怎么做」放进研究内容，立项依据只用一句话衔接。

## 立项依据的结构

科学技术价值单列一节，用 `\subsubsection`。从科学问题推出理论、方法、应用三方面的价值，每条落到本项目的具体产出。例：「理论上，检验瘤周纹理是否在控制瘤内特征后仍有增量；方法上，给出可复用的环带宽度选择流程；应用上，为术前分层提供一个可外部验证的评估工具。」不写「突破」「填补空白」「首次」。

国内外现状按主题分条。小节标题写判断，不写名词短语。

- 好：「瘤周纹理的增量价值尚未在控制瘤内特征后检验」。
- 差：「瘤周区域」。

每条先写已知（带引用），再写局限。最后一段汇总缺口，引出科学问题。

申请人已发表的论文，在相关处引用，说明团队已有积累。措辞按论文报告的内容写，不夸大。

## 研究内容的小标题

每项研究内容下用同一组小标题，按研究类型选一组，全章一致。不用加粗的（1）至（10）罗列。

- 实验研究：「设计」「对象与样本量」「流程」「指标与分析」「预期结果与判定」。
- 数据驱动研究：「数据」「方法」「验证」「判定标准」。

研究内容开头放研究框架图，各项研究内容的「设计」小标题下放该研究的设计图，做法见 `figure_guide.md`。出图失败时的占位：`【待补充：图 1 研究框架图——各项研究内容、它们之间的输入输出、对应的科学问题】`。方案借用的任务范式、量表、模型和统计方法，在正文注明出处。
