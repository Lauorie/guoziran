# 证据与措辞强度

## 怎样判断一条证据

- 只读完整摘要或全文。只有摘要片段（以「…」开头或结尾）的论文，不能作为支持证据。
- 每条证据写明 `role`：支持（supporting）还是反驳（counter）。找到反驳证据时照实记录，不要删掉。
- `basis` 写判断依据：`fulltext`（全文）或 `full_abstract`（完整摘要）。
- `ref` 写 bibkey；只有线索、没有进入 `.bib` 的，写 `lead:L<编号>`，它不计入已核实证据。

## 支持程度与正文写法

| support | 条件 | 正文写法 |
|---|---|---|
| `multi_verified` | 至少 2 条支持证据，`ref` 为台账记录为 `add` 的 bibkey，`basis` 为全文或完整摘要（完整摘要须在台账中有摘要） | 可写「多项研究表明」 |
| `single_verified` | 恰好 1 条这样的证据 | 只写「有研究报道」，不写成共识 |
| `unsupported` | 没有已核实证据 | 不写成事实。缺口类写「尚不清楚」「尚未检验」；背景类集中成段并附待补文献占位，不逐句写「可能」；或删去。见下节「无证据时的现状论断」 |
| `applicant_material` | 申请人提供的材料（只用于 `applicant_result` 类论断） | 按材料原样写，不夸大 |

`case.py validate` 会检查 `support` 是否超出证据实际能支撑的程度。有引用台账时，只有台账记录为 `add`（经 `bib_resolve` 核对）的文献计入篇数；`basis: full_abstract` 还要求台账中有该文献的摘要。`register-user` 登记的申请人文献不计数，只能支持 `applicant_material` 论断。

## 例句

- multi_verified：多项研究表明，瘤周区域特征可提供瘤内特征之外的信息\cite{a,b}。
- single_verified：有研究报道，重建核改变后部分纹理特征的重复性下降\cite{c}。
- unsupported：这一对应关系在不同扫描参数下是否稳定，目前尚不清楚。
- 缺材料：本课题组已完成预实验【待补充：预实验的样本量与主要结果】。

## 无证据时的现状论断

`unsupported` 论断分两类：

- 缺口类，即本项目要回答的认知缺口：写「尚不清楚」「尚未检验」。每个缺口写一次，不在相邻句子重复推测词。
- 背景类，即背景与现状论断，领域事实和申请人在材料中写明的现有不足：不逐句改成「可能」。集中写成一段，作为本项目对现状的判断，段末放一处可见占位，逐条列出要补的文献。占位列入占位清单。

这一段不写凭记忆的研究名称、作者、年份，也不写任何凭记忆的具体数字。每条背景类判断都要在 `evidence_map.yaml` 中有对应论断，`support` 为 `unsupported`，以便追溯。「已有研究做到哪一步」按背景类处理：在线时引用；离线时列进同一处占位。段末附了待补文献占位的背景类段落，各句视为合规。

- 反例：现有模型可能多基于单中心数据，外部验证可能不足，可解释性也可能较差。
- 正例：现有模型多基于单中心数据，外部验证中性能下降，可解释性也有限。【待补充：支持上述判断的文献——(1) 现有模型多基于单中心数据；(2) 外部验证中性能下降；(3) 已有瘤周研究所用的环带宽度】

## 哪些句子必须引用

下列句子必须 `\cite` 可引用的 bibkey，否则按上一节 `unsupported` 的两类处理，或删去。可引用的 bibkey 同时满足：(a) 是 `bib_resolve.py` 的 `added`，或 `exists` 且该 key 在引用台账中有有效记录；(b) 列在这句话所表达的论断的 `evidence` 中，`role` 为 supporting；(c) 措辞不超过该论断的 `support`。句子内容没有对应论断时，先把论断补进 `evidence_map.yaml`，或按 `unsupported` 的两类处理、删去。

- 叙述研究现状的句子。正例：有研究报道，重建核改变后部分纹理特征的重复性下降\cite{c}。反例：目前纹理特征的重复性普遍较差。
- 叙述他人方法的句子。正例：文献\cite{d}用 3 mm 环带提取瘤周特征。反例：已有方法大多采用固定环带提取瘤周特征。
- 叙述他人结论的句子。正例：多项研究表明，瘤周特征可提供瘤内特征之外的信息\cite{a,b}。反例：瘤周特征的价值已被反复证实。
- 流行病学数据。正例：某队列报告结节恶性率约为 20\%\cite{e}。反例：该类结节的恶性率较高，约为 20\%。

一个段落讲几项研究，就逐项引用，不在段末堆一个引用。反例：「研究甲发现……，研究乙发现……\cite{a,b}」。正例：「研究甲发现……\cite{a}，研究乙发现……\cite{b}」。

不要把某项具体研究的结果改写成「可能」来回避引用。反例：「某研究发现 3 mm 环带最优」改成「环带宽度可能影响性能」，却不引用。转述某项研究发现了什么的句子，必须引用该研究。

不需要引用的情形：

- 申请人自己的结果：按申请人材料写，或写成可见占位；材料本身是已入 `.bib` 的已发表论文时才 `\cite`。
- 本项目自己的设计、目标和假设：不是研究现状。
- 教科书级定义：不需引用，除非引用具体标准或指南，此时引用，或按下节「政策文件」写明名称。

## 政策文件

国家或部门的政策文件、课程标准、行业指南，不进 `.bib`。联网到发文机关的官方网站，核对文件名、发文机关与年份；核对后可在正文写明，如「《中小学综合实践活动课程指导纲要》（教育部，2017）」。网址与核对日期写入 `literature_leads.md` 的「## 官方文件」一节（`case.py init` 已建好），一份文件一行：

```text
- 《××指导纲要》；发文机关：××部；年份：20××；网址：https://……；核对日期：yyyy-mm-dd
```

核对不到的不写，按背景类论断处理，见「无证据时的现状论断」。离线时、官网查不到时、文件名或年份对不上时，都算核对不到。

正文只写文件明文规定的内容，不替文件下判断。

- 反例：国家高度重视××教育，出台了一系列政策，为本研究提供了政策依据。（没有写明文件，内容也不是文件的规定）
- 反例：《××指导纲要》（××部，20××）表明，学生的实践能力普遍不足。（文件没有这一条，是推断）
- 正例：《××指导纲要》（××部，20××）规定，该课程每周不少于 2 课时。（文件中的条款）

## 引用句中的数字

- 数字必须出自所引文献的摘要或全文。
- 摘要片段（以「…」开头或结尾）和记忆中的数字不能写。
- 一句话的数字来自多篇文献时，逐篇引用。反例：「两项研究的 AUC 分别为 0.82 和 0.88\cite{a,b}」。正例：「研究甲的 AUC 为 0.82\cite{a}，研究乙为 0.88\cite{b}」。

## 引用句的限定词

限定词要与所引文献的摘要一致：验证方式（外部、内部、随机划分）、模型组成（单独、联合）、研究设计（前瞻、回顾）、人群。摘要没有写明的，按摘要的说法改写。

- 反例：摘要写「按 7:3 随机划分训练集与验证集」，正文写成「在外部验证中 AUC 为 0.85\cite{a}」。正例：「在随机划分的验证集中 AUC 为 0.85\cite{a}」。
- 反例：摘要只报告瘤内加瘤周的联合模型，正文写成「瘤周特征单独建模的 AUC 为 0.80\cite{b}」。正例：「瘤内加瘤周的联合模型 AUC 为 0.80\cite{b}」。

## 论断条目的写法

`evidence_map.yaml` 的 `claims` 列表中，一条论断这样写：

```yaml
claims:
  - id: C1
    text: "……"
    sections: ["立项依据"]
    type: gap                    # background | gap | mechanism | applicant_result
    support: multi_verified      # multi_verified | single_verified | unsupported | applicant_material
    evidence:
      - ref: smith2020example    # .bib 中的 bibkey，或 lead:L<编号>
        role: supporting         # supporting | counter
        basis: full_abstract     # fulltext | full_abstract
      - ref: "lead:L3"
        role: counter
        basis: full_abstract
```

流程第 2 步（科学论证）新增论断时一律写 `support: unsupported`、`evidence: []`；第 3 步读完摘要后再改。`applicant_material` 只用于 `type: applicant_result`。

方法类论断（研究方案借用的任务范式、量表、模型、统计方法）：`type` 没有 `method` 一项，用 `background`，`text` 以「方法：」开头，例如「方法：用 Dice 系数评估分割一致性」。证据与措辞规则同其他论断。
