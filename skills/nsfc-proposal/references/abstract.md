# 摘要与题目的写法

写 `NSFC-ABSTRACTS.md`：题目建议、中文摘要、英文摘要、主要研究领域。有科学论证时，信息取自 `scientific_case.yaml` 和已写成的各章；科学问题、假设与术语的表述以科学论证为准。没有科学论证时（只写摘要的任务），取自申请人给的信息与项目中已有的各章。不向申请人提问；缺的信息写占位。

数字限制见 `config.yaml` 的 `abstract` 段：中文摘要字符上限 `zh_max_chars`，英文 `en_max_chars`，研究内容点数 `content_points`，推荐句数 `zh_recommended_sentences`，题目候选条数 `title_candidates`，主要研究领域的汉字上限 `field_max_chars`。

## 中文摘要：五句式

让评审一眼读懂。五个要素齐全：重要性、科学问题、可行性证据、研究内容、科学意义。每句一个功能。

| 句子 | 功能 | 占比 |
|---|---|---|
| ① 背景 | 研究对象的重要性与核心瓶颈，严格一句，不展开综述 | ≤ 15% |
| ② 科学问题 | 关键未知与当前不足，具体到机制、指标或因果链的缺口 | 15–20% |
| ③ 前期研究 | 一到两条前期发现或预实验（尽量定量），顺势提出假设 | 20–25% |
| ④ 研究内容 | 三到四点，动词开头，写清做什么、怎么做、验证什么；摘要主体 | 35–40% |
| ⑤ 意义 | 预期贡献（机制认识与方法、策略或应用），与第②句闭环 | 10–15% |

资深评审希望尽快看到申请人进入正题。背景铺垫过多是专业度不足的信号。

前期研究的两种情形：

- 申请人材料写明没有前期结果（研究基础、预实验为「无」）：第③句改为从认知缺口直接引出假设，不留「【待补充：……前期研究发现】」占位，并在 `stages.md` 记下这一偏离。
- 申请人有前期结果但缺细节：照常写可见占位。

## 英文摘要

英文是中文的忠实翻译：不扩写，不新增假设，不引入新结果。语法正确，术语与正文一致。中文摘要里的占位，英文用同样的中文占位写法。

## 格式

```text
# 标题建议
推荐标题：……
Recommended Title: ……
1) …… —— 理由：…… / EN: ……
2) …… —— 理由：…… / EN: ……
3) …… —— 理由：…… / EN: ……
4) …… —— 理由：…… / EN: ……
5) …… —— 理由：…… / EN: ……

# 中文摘要
（正文）
# English Abstract
(translation)
# 主要研究领域
（一句话）
```

- 中文摘要正文末行与 `# English Abstract` 之间不留空行。
- 中文摘要是纯文本：不用 `**`、`*`、`_`、`#` 等 Markdown 标记。申请人会把它粘贴进只支持纯文本的系统。
- 中文摘要用中文标点。需要引号时只用中文弯引号“”，不用 ASCII 双引号、全角引号、直角引号「」『』。
- 数字不用千分位逗号：写 1000，不写 1,000。
- 主要研究领域一句话，不写成多条或列表。
- 不用「国际领先」「填补空白」「首创」等营销式说法。不堆背景，不罗列方法名词；每个方法名词都服务于「要验证什么」。

## 超限时的压缩

先写一稿要素齐全、可能超限的摘要，写入后检查：

```bash
python3 S/scripts/abstract_check.py P/NSFC-ABSTRACTS.md --json
```

超限或格式不合格时，按下面的优先级压缩，再检查，最多 3 轮：

- 必须保留：研究对象、关键科学问题缺口、定量证据（若有）、核心方法名称、与问题闭环的预期贡献。
- 优先精简：程度副词、形容词修饰、「我们将」「本研究」等主语、过程性描述、「通过」「采用」等介词短语、并列重复。
- 优先删除：超出 15% 的背景、没有定量支撑的「显著」「重要」「领先」、重复句、与科学问题无关的背景。

3 轮后仍超限：停止压缩，保留当前版本，把超出的字符数记入 `stages.md` 与收尾报告，不向申请人提问。

## 题目建议

给一个推荐标题（附英文）和若干候选（条数见 `title_candidates`，每条附理由与英文翻译）。

- 长度：一般 25–40 个字符；超过 45 个字符时压缩信息密度或拆掉从句。
- 结构：研究对象 + 关键科学问题或机制 + 可验证终点，三件套最稳定。
- 动词落地：用「解析、揭示、阐明、构建、验证、评估、预测」等可验证的动词；少用「探索、探讨」作核心。
- 限定词少而准：只留会影响评审判断的那一个（如「多中心」「可解释」）。
- 题目中的关键名词与摘要的对象、假设、指标一致。
- 学科偏好：医学与生命科学多用机制叙事（「……通过……调控……的机制」）；工程、材料、化学多用「设计、制备、构建与性能调控」；信息与数理多用「面向……的方法或模型构建与理论分析」。申请人给了学部时向其偏好靠拢；没给时候选混合几种风格。

候选默认覆盖五种取向，理由要可比较，不重复：

1. 机制向：突出因果链、通路或调控关系。
2. 判据向：突出关键指标、可验证终点或评价口径。
3. 方法向：突出技术路线、模型或算法。
4. 场景向：突出亚型、应用场景或边界条件。
5. 整合向：突出跨尺度、多模态或时空动态（控制字数）。

筛选次序：对象、科学问题、可验证终点都清楚 → 与摘要主线一致、术语统一、没有空洞形容词 → 长度合适、读着顺、没有生硬的缩写堆叠。

常见错误：对象不具体（「大数据」「新材料」）；动词不落地（通篇「探索」「研究」）；从句过长，像摘要第一句；题目写机制，摘要主线却是方法。

## 写完

`abstract_check.py` 通过后，运行 `python3 S/scripts/case.py mark-written --project-root P --file NSFC-ABSTRACTS.md`（有科学论证时）。在对话中不重复粘贴全文，只报告：文件路径、题目候选条数、中英文字符数与是否超限。
